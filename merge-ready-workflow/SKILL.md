---
name: merge-ready-workflow
description: Repeats adversarial code review over a scope (uncommitted | branch | unpushed | codebase | a commit to start from), each round opened by a comment-stripping pass, until a round fixes too little to justify another, then runs a simplify workflow over the same scope and reviews the refactors the comment passes asked for once more. Use only when the user explicitly asks.
argument-hint: "<uncommitted|branch|unpushed|codebase|commit> [model]"
---

One Workflow runs adversarial review rounds, each opened by a no-comments pass that strips comments and fixes the code they excused, with freshly scouted finder dimensions, until a round fixes too little to justify another; then the simplify workflow, seeded with the refactors a comment pass flagged on the last round's fixes; then a comment pass over what simplify wrote, one review round over every refactor and constraint encoding landed since the last round, and a last pass stripping the comments that review's fixes wrote. Every stage commits its own changes. The mechanics live in [merge-ready.mjs](merge-ready.mjs), and running it needs nothing from inside it; it launches the sibling skills' [review.mjs](../adversarial-review-workflow/review.mjs), [simplify.mjs](../simplify-workflow/simplify.mjs) and [no-comments.mjs](../no-comments/no-comments.mjs), so all three must be installed. You resolve the scope, commit the user's work, describe the project, launch and report.

## Steps

1. **Resolve the arguments.** The first is the scope: exactly one of `uncommitted`, `branch`, `unpushed`, `codebase`, or a commit-ish (a sha, a tag, `HEAD~3`) naming where the work to take to a mergeable state starts, which is the `since` scope, e.g. the HEAD an earlier run ended on, so only what came after it is looked at. A token that is not a scope name is a commit-ish when `git rev-parse --verify --quiet '<arg>^{commit}'` prints a sha; if it is missing, or neither, ask the user which scope to use and stop without launching anything. An optional second argument is a model for the scout, the review implementers, the simplify appliers and the comment passes' fix stage, and no other agent; without it those inherit the session's model, except the comment passes, which run on Opus. It is a plausible model name such as `opus`, `sonnet` or `haiku`. If the token after the scope is not a model name, ask the user what they meant and stop. Any further argument: ask the user what it means and stop.

   Resolve `base`, the commit bounding the diff, once; the run pins it for every round and for the simplify phase, so a fix a round commits stays in scope for the next:
   - `uncommitted`: `git rev-parse HEAD`.
   - `branch`: the merge-base with the default branch, e.g. `git merge-base HEAD "$(git symbolic-ref --short refs/remotes/origin/HEAD 2>/dev/null || echo main)"`.
   - `unpushed`: `git merge-base HEAD @{upstream}`. If the branch has no upstream (`git rev-parse @{upstream}` fails), ask the user which remote ref bounds the unpushed work and stop.
   - `since`: the sha the commit-ish resolves to. It must be an ancestor of HEAD (`git merge-base --is-ancestor <sha> HEAD`); if it is not, say so, ask the user which commit they meant, and stop.
   - `codebase`: none; omitted from the args.

2. **Commit the user's work** so the run starts on a clean tree, after resolving `base`: the comment passes revert a rejected batch with `git checkout`, and every stage commits what it changes. When `git status --porcelain` prints nothing, skip the commit and go on to set `loopStart` below. Otherwise list the untracked files (`git -c core.quotePath=false ls-files -o --exclude-standard`); if any looks like a secret or a scratch file (`.env*`, `*.pem`, `*.key`, `id_*`, credentials, or a `tmp`, `temp` or `scratch` name), list them, ask the user what to do, and stop. When they answer, put each file they want kept out of `W` in `.gitignore` or `.git/info/exclude`, or out of the tree, as they choose. Then `git add -A` and `git commit -m "wip: work in progress before merge-ready"`, with no attribution lines or trailers. Call that commit `W`; the report names it, so the user can reword or squash it. Launch only once `git status --porcelain` prints nothing: every stage takes an uncommitted path for its own, and commits or deletes it.

   Set `loopStart` to `git rev-parse HEAD`, which is `W` when this step made one; omit it for `codebase`. The author's commits are `<BASE>..loopStart`; every commit after it is the run's.

   For a diff-bounded scope, list the paths for the launch as `files`, via Bash from the project root: `git -c core.quotePath=false diff --name-only <BASE>`. Pass them however many there are: the workflow would otherwise list them through agents copying the output, which is slower and can fail. For `codebase`, list nothing: the workflow lists them itself.

3. **Locate the four scripts.** [merge-ready.mjs](merge-ready.mjs) sits next to this SKILL.md, in the directory named by the `Base directory for this skill:` line of this skill's invocation. `review.mjs` sits in the `adversarial-review-workflow` skill folder, `simplify.mjs` in the `simplify-workflow` skill folder and `no-comments.mjs` in the `no-comments` skill folder: look for each as a sibling of this skill's folder first, then in the skills directory that holds this skill (e.g. `~/.claude/skills/<name>/`). Resolve all four to absolute paths, following symlinks (`readlink -f`). If a sibling script is missing, tell the user which skill to install and stop.

4. **Describe the project** in `context`, a string every agent of every round reads: the stack, where the agent docs live (CLAUDE.md, AGENTS.md, docs the skeptics must quote before invoking a convention), where ADRs or domain docs live, and the commit-message convention implementers and comment passes follow (name the doc, or state it). `context` describes the project; the diff's risks are the finders' to discover. A hypothesis written there ("the key risk is guidance lost in the move") is read by every finder and skeptic of every round and comes back as a finding in every dimension.

   The agents read the author's commits, `<BASE>..loopStart`, themselves. When the user told you what the diff deliberately does, put that note verbatim in `intent`; when step 2 made `W` for an `uncommitted` scope, that commit is the only intent besides the note.

   Then discover how the project verifies itself, twice, because the workflows consume it differently:
   - `checks`, for the review implementers and the comment passes' fix stage: typecheck, lint and how to run the tests that cover a given file, as commands an agent can run on the files it touched, never a watch mode. Confirm each script or target exists; if nothing trustworthy is found, omit `checks` and those agents verify by reading.
   - `checkCmd`, for the simplify phase and the comment passes' fix-up: a single non-interactive command, preferring typecheck plus tests joined with `&&`, never a watch mode. Run it once via Bash from the project root: failing checks are fine (the workflows baseline them), but if the command itself cannot run (unknown script, missing tooling), discard it. If nothing trustworthy is found, omit `checkCmd`.

   Set `pruneExts` to the comment-carrying source extensions of this repo, e.g. `[".ts", ".js", ".svelte"]`, the set for the repo rather than the extensions that happen to appear in the diff; the comment passes audit only those files. Optionally set `excludePattern`, an extended regex with no single quote and no POSIX bracket expression such as `[:alnum:]` (the comment passes match it as a JavaScript regex, where those mean something else), when the default would let a build output directory, generated code or a vendored tree of this repo into the simplify phase or the comment passes; it replaces the default rather than adding to it. The default excludes `node_modules`, `vendor`, `third_party`, `dist`, `build`, `target` and `generated` directories, minified files, lockfiles, and data, doc, image, font, archive and binary files (`json`, `md`, `svg`, `png`, `pdf`, `woff`, `zip`, `wasm`, `so` and the like). To override it, start from the `DEFAULT_EXCLUDE` constant in the `simplify.mjs` located in step 3.

5. **Launch the workflow.** Substitute the resolved paths:

   ```
   Workflow({
     scriptPath: "<absolute path to merge-ready.mjs>",
     args: { scope: "<scope, since for a commit-ish>", root: "<absolute project root>", base: "<commit, omitted for codebase>", reviewScript: "<absolute path to review.mjs>", simplifyScript: "<absolute path to simplify.mjs>", noCommentsScript: "<absolute path to no-comments.mjs>", context: "<project description>", files: [<paths, omitted when step 2 listed nothing>], loopStart: "<HEAD after step 2, or the dead run's; omitted for codebase>", intent: "<the author's note, omitted when none>", checks: "<check commands, omitted when none found>", checkCmd: "<single check command, omitted when none found>", pruneExts: [<extensions>], excludePattern: "<regex, omitted to keep the default>", model: "<model argument, omitted when not given>" }
   })
   ```

   Pass `files` and `pruneExts` as real JSON arrays. The script validates the args and throws on a missing one.

   **If the run dies** (a session limit, a killed task), never resume it with `resumeFromRunId`, whatever the harness suggests; relaunch it by [RELAUNCH.md](RELAUNCH.md) in this skill's folder.

   What the result means. A round continues the loop when its `decision.reasons` is non-empty; only a `converged` loop goes on to simplify. A file two rounds in a row found clean, with nothing touching it since, is left out of later rounds (`setAside` counts them) until a fix or comment pass touches it; a quiet round with files set aside is followed by a `confirmation` round over the full scope, and the loop converges only on a quiet round with nothing set aside. `stopReason` is `converged`, `max-rounds`, `possibly-dirty`, `comments-failed` (a comment pass threw or could not commit, so the tree may be dirty), `scope-empty` (nothing to review), `prepare-failed` (the launch state could not be read), `review-failed`, `agent-failed` or `agent-limit` (the runtime's 1000-agent cap or token budget stopped the loop), with `stopDetail` saying which round and agent. Each round's `comments` is the no-comments.mjs result of the pass that opened it (null when `commentsSkipped` says why none ran), and its `review` carries only `finderFailures` and `findings` from the review.mjs result; the other fields REPORT.md reads are reported once, by the loop-wide notes below.

6. **Report.** Open with one table over the rounds: round (marking a `confirmation` round), files set aside, comments deleted and MUST KILL refactors applied by its opening pass, finders, findings registered and confirmed, fixed and covered (with the medium-or-higher count and how many finders reported them), fixes that changed production behaviour (with their ids), and the decision with its reasons. Then state the stop reason in a sentence; for `scope-empty` say there was nothing to review; for `max-rounds`, `possibly-dirty`, `comments-failed`, `prepare-failed`, `review-failed`, `agent-failed` and `agent-limit` state prominently that the review never became quiet, quoting `stopDetail`, and that simplify did not run.

   Then report each round. Its `comments` by `WORKFLOW-REPORT.md` in the `no-comments` skill folder, listing every encoding prominently for the user to check. Its `review` the way the single-run skill does: read `REPORT.md` next to the `review.mjs` located in step 3 and apply it to that round's `review`, taking `excludedKinds` from the top level and leaving the notes on checks, dirty paths and the implementer model to the loop-wide notes, with the finding numbers prefixed by the round (`2.5` is finding 5 of round 2) so numbering stays unique across the report, and each refuted finding on one line: its title, the skeptic and its `refuteReason`. Leave REPORT.md's pre-existing and serious findings out of the rounds: list them once, in a section after the last round, each with its location, `description` and `refuteReason`, merging the reports several rounds make of the same defect. Add the round's `unassignedFiles` when present, saying the scout left them out and a catch-all finder reviewed them. When a round's triage `failed`, say its medium-or-higher fixes were assumed to have changed production behaviour. A round whose `review` is null gets its `error` instead.

   Then, in order:
   - `seedsComments`, by the same `WORKFLOW-REPORT.md`: the flags pass over the last round's fixes, whose seeds simplify judged. When `simplify.ran` is false, simplify did not run: list every seed as that file says for unjudged seeds.
   - When `simplify.ran`, `simplify.result` the way the simplify skill does: read `REPORT.md` next to the `simplify.mjs` located in step 3 and apply it; simplify committed its own changes. When simplify did not run, say why from `simplify.skipped` and `simplify.error`.
   - `afterSimplifyComments`, by the same `WORKFLOW-REPORT.md`: the pass over what simplify wrote.
   - The closing review. When `closingReview.ran`, list its `files` (the refactors and encodings it reviewed) and report its `review` like a round, numbering its findings `C.1`, `C.2` and so on; state prominently every fix in `mediumOrHigherFixes`, saying the closing review never extends the loop, so nothing reviewed those fixes after it. Give its `error` when its review is null, and `unassignedFiles` when present. When it did not run, give `closingReview.skipped`.
   - `finalComments`, by the same `WORKFLOW-REPORT.md`: its `mustKills.reported` are refactors left for the user.
   - `closingSkipped`, prominently when present: the closing stages stopped there.

   Close with the loop-wide notes:
   - `agentLimit` not null: state prominently that the runtime's agent cap or token budget ended the run, quoting it, so the agents reported dead or failed after it never ran, the tree may be dirty, and only a fresh run can continue.
   - `checksConfigured` false: state that no check command was found for the review rounds, so every fix was verified only by reading.
   - `possiblyDirty` non-empty: state prominently that a cleanup after an implementer could not restore the tree: list these paths, which may hold partial hunks; the entry `(cleanup agent failed: run git status)` means the cleanup agent itself died, so which paths are dirty is unknown. Either way the user must inspect `git status`.
   - When `model` is not null, say which model ran the scout, the review implementers, the simplify appliers and the comment passes' fix stage.
   - Name `W` when step 2 made one, so the user can reword or squash it.
   - End with the final HEAD (`git rev-parse --short HEAD`) and the command that continues from it, looking only at what comes after: `/merge-ready-workflow <sha>`.
