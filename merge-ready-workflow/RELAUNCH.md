# Relaunching a dead merge-ready.mjs run

Never resume it with `resumeFromRunId`, whatever the harness suggests. Each round's review misses the cache partway through and re-runs live against a tree that already holds the fixes, so the loop reports `converged` on a round that fixed nothing. Relaunch instead: redo steps 1 to 4 with the same scope and `base`; the workflow reads the launch state afresh, so the relaunch loses only the round that was in progress. Set `loopStart` to the commit the dead run started from rather than HEAD, so the fixes it committed are set apart from the author's commits: find the dead run's earliest `commitSha` among its `implement #N` results in its `journal.jsonl`, take its parent (`git rev-parse <sha>^`), and confirm it with `git merge-base --is-ancestor <loopStart> HEAD`. After several dead runs, keep the first run's `loopStart`. When the dead run committed nothing, HEAD is still right; when its journal cannot be found, use HEAD and tell the user its fixes will read as the author's commits.
