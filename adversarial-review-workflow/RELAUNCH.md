# Relaunching a dead review.mjs run

Never resume it with `resumeFromRunId`, whatever the harness suggests. The finders and skeptics start their agents in the order earlier ones finish, so the cache misses partway through and the rest re-run live against a tree that already holds the fixes, where the skeptics refute every finding as already fixed. Relaunch instead with the same scope and model, but take `base` from the dead run's launch args in its `journal.jsonl` rather than resolving it again in step 1: against the current HEAD, `uncommitted` would resolve to the dead run's last fix and leave nothing to review, and a relative commit-ish such as `HEAD~3` would name a different commit. Then redo steps 2 to 5; the dead run's `W`, if it made one, is already committed, so step 2 finds a clean tree unless the dead run left partial hunks, which `git status` shows and the user must inspect first. Take `authorEnd` from the same launch args rather than HEAD, so the fixes the dead run committed, and those of any run it relaunched, read as this review's rather than the author's. For `codebase`, omit both `base` and `authorEnd`.
